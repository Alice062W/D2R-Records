# Set Items: Site Data vs D2R.world Comparison
Generated by comparing `data/sets.json` against D2R.world's set-item pages (`C:\d2r-world-all\sets_all`, English), treated as ground truth per the same convention established for the runeword comparison (`runeword_comparison_d2rworld.md`). This is a **diagnostic listing, not an applied fix** -- nothing in `data/sets.json` has been changed by this pass.
## Methodology
- Each D2R.world set page has a top "bonus summary" block (every 2-/3-/full-piece bonus for the set, in one place) followed by one block per item with its own base stats + "Magic Properties" list.
- For each set, this report unions ALL property/bonus text found anywhere on our side (`properties` + `setPiecesBonuses` + `setFullBonus`, across every item in the set) against ALL property/bonus text found anywhere on D2R.world's side (the summary block + every item's own list), normalizing away numbers and a trailing "(N)"/"(Completed Set)" tag so wording/number differences don't cause false negatives -- this catches genuinely missing or extra content regardless of which item or tier it's attached to on either side.
- Per-item base stats (required level, required strength, defense range, base item name) are compared directly by item name match.
## ⚠️ Structural finding: per-item partial-set bonuses are collapsed
In real D2R (and on D2R.world), **each individual set item can carry its own, different, 2-/3-/4-piece bonus** -- e.g. for Aldur's Watchtower, Aldur's Stony Gaze (helm) grants `+15 to Energy` at 2/3/full pieces while Aldur's Deception (armor) separately grants `+15 to Vitality` at 2/3/full pieces on that SAME set. Our `data/sets.json` stores exactly one `setPiecesBonuses` array per set and **duplicates it identically across every item in that set** -- confirmed for all 35 sets currently in the file (zero sets have any per-item variation). This means every per-item partial bonus that isn't the one our data happened to capture shows up below as "missing" -- that's not 35 independent bugs, it's one shared modeling gap. Fixing it properly means adding real per-item `setPiecesBonuses` to the data model, not just editing labels.
