# Set Items: Site Data vs D2R.world Comparison
Generated by comparing `data/sets.json` against D2R.world's set-item pages (`C:\d2r-world-all\sets_all`, English), treated as ground truth per the same convention established for the runeword comparison (`runeword_comparison_d2rworld.md`). This version follows a thorough correction pass, not just diagnosis: the D2R.world parser itself had several bugs (a top "bonus summary" block truncated by unbulleted multi-line properties, occasional runs into footer-ad text and the next item's name with no separator, and silent overwriting when an item shows a base defense/damage value AND a final value after its own magic properties are applied) -- fixing those surfaced real data bugs the first pass missed entirely. Applied so far: the "Requirements --NN%" double-dash typo; missing "(Class Only)" qualifiers and several outright wrong skill-tab bonuses (e.g. Griswold's Legacy items granting generic Combat Skills/Masteries/Warcries instead of their real Paladin Aura bonuses); all 21-item base-vs-enhanced defense/damage pairs, now stored as `baseDefense`/`baseOneHandDamage`/`baseTwoHandDamage` alongside the existing (now corrected-to-final) `defense`/`oneHandDamage`/`twoHandDamage` fields -- the site's `ItemStatCard` only ever reads the latter, so the base value is naturally hidden without any UI changes; every required-level/-strength/defense/base-item-name numeric mismatch found; a "Naj's Puzzler" Teleport charm with its skill level and charge count literally swapped; a couple of wrong poison-damage values; the "Additional" prefix D2R.world uses on a stacking bonus's 2nd+ tier; and the common "+50%/150%/200%/250% Damage to Undead" property missing from several items. Warlord's Glory was removed entirely (doesn't exist on D2R.world, not obtainable in-game). Remaining known gaps (not yet applied): a handful of items still missing "Character Displays Aura/Fade Effect" flavor text, static "Socketed (N)" base-item property lines (no schema field for this yet), and a few small residual wording differences -- see the per-set detail below.
## Methodology
- Each D2R.world set page has a top "bonus summary" block (every 2-/3-/full-piece bonus for the set, in one place) followed by one block per item with its own base stats + "Magic Properties" list.
- For each set, this report unions ALL property/bonus text found anywhere on our side (`properties` + `setPiecesBonuses` + `setFullBonus`, across every item in the set) against ALL property/bonus text found anywhere on D2R.world's side (the summary block + every item's own list), normalizing away numbers and a trailing "(N)"/"(Completed Set)" tag so wording/number differences don't cause false negatives -- this catches genuinely missing or extra content regardless of which item or tier it's attached to on either side.
- Per-item base stats (required level, required strength, defense range, base item name) are compared directly by item name match.
## Correction to an earlier version of this report
An earlier version of this report claimed our data collapses each item's own partial-set bonus into one shared, duplicated list. That was wrong -- it was an oversight in the comparison script, not a real gap: `data/sets.json` items DO carry their own distinct per-item bonus in the `setBonuses` field (e.g. Aldur's Stony Gaze's helm-specific `+15 to Energy` at 2/3/full pieces, separate from Aldur's Deception's `+15 to Vitality`), matching D2R.world correctly. The comparison script simply never read that field on its first pass, so every per-item bonus line showed up as "missing" even though it was already there. `setPiecesBonuses`/`setFullBonus` are a separate, intentionally-shared pair of fields holding the SET's own combined bonus (identical for every item in the set, which is correct -- that's what a full-set bonus is). This report has been regenerated with the fix.
